# Godot 2D 工作流

只读取当前任务需要的参考，不将所有参考加载到上下文。

## 先定位

读取用户目标与项目规则，检查项目根、Godot 完整版本、主场景、已有语言和测试入口、未提交改动。桥接可达不等于打开了正确游戏；核对实际项目、连接实例和当前场景。

## 选择本次实现步骤

简单改动直接处理。需要规则设计时，先用短说明写清输入、状态、输出和检查方法；不要机械创建设计文档或团队。优先原有架构和工具，不迁移语言/测试框架/关卡编辑器。

读取实际 MCP schema，用上游工具启用当前必需的 Toolset。工具未出现时检查目录更新，不虚构调用或绕过宿主。CLI 只用已允许且存在的程序，安装缺失项需用户批准。

## 做一组能验证的修改

代码用原生文件/终端工具；场景树、未保存编辑器状态优先引擎工具。保留用户改动；写后保存、回读。超时/断线/取消后先观察是否已应用。尽量小范围 diff，不全工程格式化。

## 验证

执行与改动相称的解析/编译、测试和运行。逻辑测试、画面检查、导出结果分开报告。界面任务需实际显示并检查；没有视觉能力就明确未核验。不得只凭工具返回 success 判断。

## 按任务读取

- 构建、测试、Headless、C#/C++：[testing.md](references/testing.md)
- 图片、音频、地图和开源素材：[assets.md](references/assets.md)
- 日志、错项目、超时、视觉与性能：[debugging.md](references/debugging.md)
- 导出、模板、发布前验证：[release.md](references/release.md)

## 收尾

简要说明改动、验证命令/工具与结果、证据、剩余风险。仅终止本轮拥有的进程；不关闭用户原有编辑器、不安装下一套工具、不自动发布。
