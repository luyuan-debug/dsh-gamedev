# 调试与恢复参考

先从当前日志和实际状态定位，不重新造架构。尽量最小复现→修复→同路径回归。记录时间、场景、输入和环境，区分旧日志和本轮新报错。

连接失败：分别检查 MCP 进程、协议协商、编辑器 addon、地址/端口、目标项目、版本。一个 bridge 只能有一个活动编辑器；新连接可能替换旧项目 [S07]。不要为了修复端口冲突杀未知进程。

写超时：上游 `may_have_applied`、`persisted`、部分失败必须保留。再次创建可能重复节点，再次导出可能覆盖文件。先回读，再根据实际状态选择修复。撤销不是通用事务；一些资源写入不在 UndoRedo 中 [S08]。

工具目录：启用 Toolset 后需看到 DSH 真正注册的 schema；返回 schema 文本不够。未知工具调用失败时不要用任意代码执行绕过权限。上游 Toolset 开关不是每 Session 独立安全边界。

视觉：取得真实运行画面而非仅编辑器截屏；记录图像来源、分辨率、当前场景、截图时间。支持图像的模型应实际接收到图像块。无视觉模型时可验证日志/语义状态，但标记视觉未验收。不要用“已经保存 screenshot.png”替代看图。

交互：验证按下和释放、焦点、暂停后恢复、重复开关菜单。输入工具取消/超时后释放本轮持有输入，避免一直按住移动键。Gua 有语义定位/动作时优先，但原有项目没装时不强行接入。

性能：记录真实帧时间/内存/CPU与同一负载基线，区分编辑器、debug、release 和 headless。运行模拟有副作用，使用一次性存档，不读写用户正式存档做压力测试。
