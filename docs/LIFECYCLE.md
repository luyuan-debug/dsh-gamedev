# 连接与故障排查

每个开发目录对应一个 Godot 工程，同一时间由一个开发会话使用编辑器连接。需要切换游戏时，请使用另一个开发目录；不要把正在运行的会话改指向另一工程。

## 常见操作

| 情况 | 接下来怎么做 |
| --- | --- |
| 第一次使用 | 保存有效的连接设置，启用桥接，再新建 Godot 2D 会话 |
| 提示另一个会话正在使用连接 | 返回那个会话继续开发，或正常关闭它后再新建会话 |
| 关闭桥接后显示 `STOPPING` | 等待连接和子进程清理完成；此时不会启动第二条连接 |
| 重新启用同一个项目的连接 | 等待清理结束，仍有效的原会话可以重新连接 |
| 修改项目、Godot、桥接程序或地址 | 保存设置后新建 Godot 2D 会话 |
| 插件重新加载后旧会话不能连接 | 新建会话，以使用重新加载后的插件 |
| 端口被占用 | 查明占用来源，或为新的开发目录选择其他空闲端口 |

## 如何判断连接正常

`MCP_READY` 表示连接程序已经初始化。编辑器是否在线，还要看最近一次 `godot_health_check` 的结果和时间：确认返回的是当前工程与预期 Godot 版本。

状态页记录的是最近一次检查，不是实时在线监控。开始修改前应确认连接正常；修改后仍需保存、检查日志并查看运行效果。

## 中断、超时或取消后怎么办

修改、删除、导出或输入操作可能已经执行，只是答复没有返回。先恢复连接，再读取文件或场景的当前状态，确定哪些操作已生效，然后决定如何继续。

连接程序最多自动尝试恢复三次，间隔从 300 毫秒增加到最多 3 秒。**恢复连接不会自动重做刚才的命令。** 关闭开关或取消操作也不会自动撤销已有修改。

若健康检查也失败，先保存原始错误，确认启动终端仍在运行、编辑器插件已启用、工程和端口一致。不要为了处理端口冲突而结束来源不明的进程。

## 输入与运行

检查游戏交互时，同时确认按键按下和释放、窗口焦点、暂停与恢复。中断后若角色仍持续移动，请在 Godot 中停止游戏并检查输入状态。

发布、覆盖文件、外部导入等操作仍受 DSH 的审批设置约束。工具中的 `confirm` 参数不会代替你的批准。

## 给维护者的说明

插件按会话对象和当前配置记录连接的使用者。会话 ID 相同不代表它是原来的对象；插件重新加载后，旧会话也不能借用新连接。关闭时先拒绝新调用，再释放原连接，避免两个编辑器同时接收修改。

本地启动保护代码会核对工程、Godot 和编辑器插件版本，并拒绝第二个编辑器替换连接。它用于避免连接到错误工程，不能防范拿到令牌后伪造身份的本机程序，也不能替代文件访问控制。实现见 [bridge/README.md](../bridge/README.md)。

自动化测试位于 `tests/lifecycle.test.mjs`。真实应用与游戏的测试范围见 [测试说明](VERIFICATION.md)。
