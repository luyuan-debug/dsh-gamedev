# 生命周期与故障恢复

本插件使用 DSH 原生 preset、scope 和 MCP 客户端。一个隔离配置只提供一个 Godot 2D 预设；同一时刻只有一个确切的 Agent 对象可以拥有编辑器连接。复用会话 ID 不等于复用拥有权，其他会话不能替换正在使用的拥有者。

## 状态与操作

| 情况 | 插件行为 | 使用者下一步 |
| --- | --- | --- |
| 未启用、未配置或可选工具缺失 | 核心桥接不自动安装；未允许或不可用的可选项不进入能力提示 | 完成核心必填项并显式启用；独立处理可选项 |
| 当前有效会话请求连接 | 锁定该会话对象与配置目标，通过原生 MCP 初始化 | 等待 `MCP_READY`，运行真实健康检查 |
| 另一会话请求已有活连接 | 拒绝接管 | 使用拥有者，或正常关闭它后新建会话 |
| 关闭桥接、关闭拥有者或卸载定义 | 立即撤销派发权，原生连接进入清理 | 等待 `STOPPING` 完成；在途写入先回读 |
| 清理期间重新启用或创建会话 | 请求可排队，旧连接排空前不启动新连接 | 等待清理，不抢端口或结束未知进程 |
| 修改项目、Godot、桥接程序或端点 | 旧会话保持原绑定并拒绝后续调用 | 新建使用已保存目标的 Godot 2D 会话 |
| 插件热重载 | 旧定义失效，不能再次获得当前定义的连接；当前定义等待旧实例清理 | 新建采用当前预设的会话，无需强迫旧会话热迁移 |
| 原生 MCP 传输断开 | 原生客户端按 300 ms 起、最多 3 s 间隔、最多 3 次恢复连接 | 读取原始错误，健康检查后回读；写入不会自动重放 |
| 恢复耗尽、端口被占或项目不符 | 明确失败，不杀进程、不改目标、不放宽保护 | 修复本次环境后显式重新请求，必要时新建会话 |

配置保存会先验证；无效草稿不改变旧有效配置。关闭采用已接受的开关，不能被无关的无效草稿阻挡。仅改变可选项或健康诊断不会把原会话静默转向另一项目。

## 两个不同的“连接成功”

`MCP_READY` 只表示该次原生 MCP 初始化已经完成。编辑器在线诊断来自最后一次真实 `godot_health_check`；时间戳与结果是一次观察，不是持续监控。先确认健康返回的项目根与 Godot 版本，再做读取和开发。开发后还要保存回读、解析、运行和画面核查。

固定桥接的最小启动保护器在发送命令前校验项目身份，拒绝错误项目与第二编辑器替换。它不改变上游工具名、schema、错误码或授权语义。掌握令牌并伪造身份的恶意本机进程不在这层保护保证内；端口与身份检查也不是通用文件沙箱。

## 失败与取消

调用最多经过一条串行编辑器通道。原生传输恢复不会重试调用者的命令，特别是修改、删除、导出和输入操作。原生错误可能表明已经派发，但未收到成功答复；保护器保留已知的可能写入/落盘诊断。不要把 `TIMEOUT`、取消、断开或关闭开关解释为“未写入”。

先用新的一次读取确认项目实际状态，核对文件、节点、场景与持久化结果，再决定是否重新执行。读取本身失败时保留原始错误，先恢复连接。插件不替用户进行事务回滚。

输入工具只接受有限规模且成对释放的序列，保留原生审批。名义游戏时间上界不等于暂停或时间缩放下的绝对墙钟保证，取消/断开后的释放需真实引擎验收。破坏性、导出、外部导入与不透明执行继续走原生 ask；`confirm=true` 或启用 toolset 不代替批准。

## 验证范围

`tests/lifecycle.test.mjs` 检查同对象重复请求、第二拥有者、复用 ID、禁用、延迟清理、启动期撤销、永不完成的 ready、同步重入、定义交替屏障和目标变化等并发边界。它使用合成原生 mount，证明类的约束，不证明真实宿主完成清理。

真实 DSH 验收还需记录当前定义/退休定义、会话对象、原生 fork、子进程与监听端口的对应关系，并验证重连不重放写入。真实 Godot 和模型开发单独记录。最终证据见 [VERIFICATION.md](VERIFICATION.md)，旧版结果不直接继承给 0.2.0。
